New domain from template

Templates are starting points with sane presets — WAF log-only, and caching or compression where it fits the site kind. Adjust settings afterwards; no template ships firewall rules. Creating a domain reloads the configuration, which resets per-domain counters and stage state, exactly as a manual reload does.

Certificate and key must both be set, or both be empty. Leave both empty when using Cloudflare or autoSSL.

Import domains

Bulk-create domains from JSON or CSV. Every entry is validated first — an invalid import is rejected and nothing changes. Importing reloads the configuration, as creating a single domain does.

JSON: an array of objects with name, backend, and optional scheme, template, certificate, key. CSV: a header row (name,backend,scheme,template,certificate,key) followed by one domain per row.

Import from nginx / Apache

Convert nginx server blocks or Apache vhosts into SonuShield domains. Only the documented subset is imported (server names, proxy backends, TLS cert paths); rewrites and other directives are reported, never silently dropped. Preview first — applying reloads the configuration, as creating a domain does.

Rule simulator

Evaluate an expression against sample request fields, without enforcing anything. Leave the sample empty to test against zero values.

Field names are the same as in rules. Unknown fields are rejected. Values use the request types: ip.src an IP string, counters and proxy.stage integers, proxy.* flags booleans, the rest strings.

Rule packs

Import a rule pack — a JSON document with pack metadata plus a rules array — from a file path on the server or a URL. Every rule is validated first and the import is all-or-nothing. Packs are operator-chosen: SonuShield ships no bundled packs and endorses none.

Export / import rules

Export downloads the rule set as JSON. Import validates every rule first — an invalid import is rejected and nothing changes. Replace mode overwrites the whole rule set; append mode adds to it.

Visual rule builder

Build an expression from field, operator, and value pickers. Conditions combine with AND. About & limits

SonuShield Dashboard — the control panel served by the proxy itself. No build step, no external resources: everything on this page is served from the single proxy binary and works offline.

What this dashboard can do

  • Show live request rates, totals, CPU/RAM, and the current stage.
  • List configured domains with backends, schemes, and live summaries.
  • Change the stage, lock it, or switch under-attack mode on and off (runtime-only; a reload resets it).
  • Add, edit, and delete firewall rules — saved to config.json immediately, with a backup kept.
  • Edit domain thresholds, proof-of-work, and WAF-lite settings — saved to config.json immediately.
  • Show recent passed requests, clear logs, load attack reports, and export them as JSON or CSV.
  • Reload the configuration from config.json after validating it; an invalid config is rejected and the running proxy is untouched.
  • Create domains from templates and bulk-import domains from JSON or CSV.

What still needs the config file

  • Secrets — API/admin secrets, challenge keys, the Telegram bot token, and the email password are never shown or accepted here. Edit config.json on the server. Admin/API secret changes need a restart.
  • Removing domains, and changing backends, schemes, and certificate paths — edit config.json, then use Reload config here. New domains can be created in the Domains view.
  • Proxy-wide settings (timeouts, rate limits, GeoIP databases, auto SSL, metrics, logging) — edit config.json, then use Reload config here.

Security notes

  • This page is only served on the admin-secret path. Anyone without the exact path never receives it.
  • All data comes from the existing API v2 endpoints with the X-SonuShield-Secret header. Your API secret stays in this tab's session storage and is cleared when you click “Forget secret” or close the tab.
  • Your theme (Dark/Light) and language (English/Hindi) choices are stored in this browser's local storage and never sent to the server.
  • Keep both secrets out of screenshots, chat logs, and shared URLs. Rotate them in config.json if they ever leak.
