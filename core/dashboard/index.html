Add a rule

Fields: ip.*, http.*, proxy.* — see the firewall-rules docs. Expressions that do not compile, or use an unknown field, are rejected and nothing changes.
0 allow, 1–3 challenge, 4+ block, +N/-N adjust and continue.

Rule simulator

Evaluate an expression against sample request fields, without enforcing anything. Leave the sample empty to test against zero values.

Field names are the same as in rules. Unknown fields are rejected. Values use the request types: ip.src an IP string, counters and proxy.stage integers, proxy.* flags booleans, the rest strings.

Export / import rules

Export downloads the rule set as JSON. Import validates every rule first — an invalid import is rejected and nothing changes. Replace mode overwrites the whole rule set; append mode adds to it.

What the actions mean

ActionMeaning
0Allow — request is whitelisted, never challenged.
1Cookie challenge — invisible, passed automatically by most good bots.
2JavaScript proof-of-work challenge — stops most bots, including good ones.
3Captcha — visitor must solve a visual captcha.
4 or higherBlock — request is blocked outright.
+N / -NRaise or lower the current suspicion level by N, then keep checking further rules.

Change the stage

Stage changes apply immediately and are runtime-only: a config reload or restart returns the domain to automatic switching. Under-attack mode locks Stage 3; Automatic turns it off.

What each stage does

StageChallengeEffect
Stage 1Cookie challengeInvisible; stops simple attacks.
Stage 2Proof-of-work JS challengeStops more advanced bots.
Stage 3Custom captchaLast resort; stops most malicious requests and good bots too.
Above 3BlockAll requests blocked (only when manually locked above 3).
Stage changes are runtime-only. Locking a stage here has the same effect as the terminal stage command, and a reload or restart returns the domain to automatic switching. There is no need to use the terminal for stage control.

About & limits

SonuShield Dashboard — the control panel served by the proxy itself. No build step, no external resources: everything on this page is served from the single proxy binary and works offline.

What this dashboard can do

  • Show live request rates, totals, CPU/RAM, and the current stage.
  • List configured domains with backends, schemes, and live summaries.
  • Change the stage, lock it, or switch under-attack mode on and off (runtime-only; a reload resets it).
  • Add, edit, and delete firewall rules — saved to config.json immediately, with a backup kept.
  • Edit domain thresholds, proof-of-work, and WAF-lite settings — saved to config.json immediately.
  • Show recent passed requests, clear logs, load attack reports, and export them as JSON or CSV.
  • Reload the configuration from config.json after validating it; an invalid config is rejected and the running proxy is untouched.

What still needs the config file

  • Secrets — API/admin secrets, challenge keys, the Telegram bot token, and the email password are never shown or accepted here. Edit config.json on the server. Admin/API secret changes need a restart.
  • Adding or removing domains, backends, schemes, and certificate paths — edit config.json, then use Reload config here.
  • Proxy-wide settings (timeouts, rate limits, GeoIP databases, auto SSL, metrics, logging) — edit config.json, then use Reload config here.

Security notes

  • This page is only served on the admin-secret path. Anyone without the exact path never receives it.
  • All data comes from the existing API v2 endpoints with the Proxy-Secret header. Your API secret stays in this tab's session storage and is cleared when you click “Forget secret” or close the tab.
  • Your theme choice (Dark/Light) is stored in this browser's local storage and never sent to the server.
  • Keep both secrets out of screenshots, chat logs, and shared URLs. Rotate them in config.json if they ever leak.
